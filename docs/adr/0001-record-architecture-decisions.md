# 1. Record architecture decisions

- Status: accepted
- Date: 2026-10-17

## Context

This project is built to production standards. Reviewers need to see *why* each choice was made, not just what was chosen.

## Decision

We record significant decisions as lightweight ADRs (Michael Nygard format) in `docs/adr/`, numbered sequentially. An ADR is never edited after acceptance. To change a decision, a new ADR supersedes the old one.

## Consequences

Each ADR adds a few minutes of writing, and in return the reasoning stays reviewable.
