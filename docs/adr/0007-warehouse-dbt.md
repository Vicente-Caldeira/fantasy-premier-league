# 7. dbt warehouse over the lake: DuckDB locally, BigQuery in prod

- Status: accepted
- Date: 2026-10-17

## Context

Five sources need joining into one model of matches and players. Each names clubs differently, and some carry known errors. The transformations should be reviewable SQL with tests, and they should run on a laptop for free as well as in the cloud.

## Decision

- **dbt** models read the silver Parquet tables directly (`read_parquet` on the lake path) through:
  - `staging` views, one per source table, mapping each source's club identifiers to a `team_key`;
  - `intermediate` views that show every source's view of a match side by side;
  - `marts` tables: `dim_teams` and `fct_matches`.
- **Targets:** DuckDB in dev (session pinned to UTC) and BigQuery in prod, which has a per-query bytes-billed cap. The SQL sticks to portable constructs and cross-database macros (`dbt.hash`).
- **Team crosswalk:** a seed generated by `dbt/scripts/build_team_crosswalk.py`. It assigns every name or id the FPL team code it co-occurs with most often, matching on (season, date, score), and fails if any assignment is ambiguous. Nothing is hand-typed.
- **Cross-source tests:**
  - Strict: FPL, football-data and Understat must agree on every score, and FPL and football-data on every played date. There must be exactly 380 matches per season; since the mart is a full outer join, a mapping error shows up as extra rows.
  - Warn-only: the known upstream defects (6 wrong Elo-Insights scores, Understat kickoffs off by −12..+8h). The affected values aren't used where a better source exists.
- **Dagster** loads the dbt project as assets via `dagster-dbt`. Source `meta.dagster.asset_key` links the models to the ingestion assets, which gives lineage from bronze to marts. The manifest is built at image build time.

## Consequences

- `dbt build` is the single gate: models and tests run together, and a failing strict test fails the Dagster run.
- `dbt-bigquery` pins `google-cloud-storage < 3.2`, which holds `gcsfs` at 2025.12. Revisit when the pin is lifted.
- CI runs `dbt parse`. A data-backed `dbt build` in CI needs a synthetic lake (follow-up).
